What changed in this commit (hardening pass):
  * hive/scheduler.py:
    - `select_best_job` no longer double-sorts when the worker is starved
      (boosts deficit only when is_starved, then sorts once).
    - `MiniMaxPoolState.can_assign` now explicitly consults the
      `MINIMAX_PER_WORKER_MAX` constant instead of relying on the implicit
      "one held lease per worker" invariant. The reason string includes the
      live per-worker cap value so a future bump to the constant is
      reflected everywhere.
  * agent_bus.py:
    - The two hardcoded `5` MiniMax-pool literals in the dequeue flow
      (the pool-saturation `>= 5` gate and the `pool_cap: 5` event payload)
      now use the imported `_SCHED_MINIMAX_GLOBAL_MAX` constant from
      `hive.scheduler` — no more drift between the policy and the bus.
  * test_scheduler.py:
    - +44 new defensive checks: malformed `current_load` JSON (NaN, inf,
      negative, out-of-range, non-numeric strings, None) yields sane
      profiles instead of crashing; flat-float heartbeat payloads (legacy)
      still parse; `MINIMAX_PER_WORKER_MAX` is the source of truth for the
      per-worker cap reason string; `build_pool_snapshot` normalises
      whitespace + case; starvation boost preserves priority ordering;
      deterministic scores across fresh worker profiles (no hidden globals);
      `MiniMaxPoolState.assign` is documented as caller-guarded (not
      self-checking).
  * test_defect_fixes.py:
    - +2 new SchedulerDequeueTests:
      * `test_dequeue_local_eih_routes_share_pool_with_general_workers` —
        pool saturation (5/5 MiniMax leases) does NOT block a general
        worker on the grok-4.3/xai route from claiming a queued
        local/EIH job. The MiniMax cap is a route-class cap, not a
        worker cap.
      * `test_dequeue_minimax_pool_observability_event_is_emitted` —
        the structured `minimax.pool.denied` event is emitted on the
        bus with the urn + reason + pool_active + pool_cap payload so
        fleet operators can grep the events table (not stderr) for
        saturation signals. Hardcoded `pool_active == 5` and
        `pool_cap == 5` assertions now use the live
        `sched.MINIMAX_GLOBAL_MAX` constant.
    - `from hive import scheduler as sched` import added at module
      scope (previously implicit via agent_bus).

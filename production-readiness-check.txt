What changed in this commit (round-4 hardening):
  * hive/scheduler.py:
    - `MiniMaxPoolState.assign` is now self-checking: raises ValueError
      when the same worker urn already holds a non-None lease, eliminating
      the entire bug class of "caller forgot to honour a can_assign deny"
      (the second assign is loud, not silent). The global cap is still
      not self-checked because can_assign consults it explicitly with a
      rich reason string.
    - `score_candidate` now defensively falls back to ROLE_GENERAL when
      a WorkerProfile has an unknown role (instead of KeyError on the
      role-penalty lookup). `derive_worker_role` is the canonical source
      and always returns a known role, but a future caller could construct
      a WorkerProfile directly with an unknown role — we shouldn't
      KeyError on the score lookup.
  * test_scheduler.py (+9 new defensive checks, 108 -> 117):
    - assign raises ValueError on double-assignment (mentions per-worker cap).
    - assign raises ValueError on empty worker urn.
    - assign on a clean state: counter increments by 1, leases_by_worker
      stores the lease exactly.
    - release-then-reassign is the supported path (dict slot for the urn is
      reused, not raised).
    - score_candidate falls back to ROLE_GENERAL penalty for an unknown role
      (no KeyError on a malformed WorkerProfile).
    - For ordinary work, general role beats review role (penalty 0 < 1).
    - For ordinary work, general role beats data role (penalty 0 < 1).
    - review and data roles share the same +1 non-build penalty.
    - build-required role-penalty ordering: build=0 < review=2 < data=3
      < general=4.
  * test_defect_fixes.py (+1 SchedulerDequeueTest, 8 -> 9):
    - test_dequeue_atomic_two_pollers_only_one_wins: two workers race
      for the same single queued job; the dequeue flow uses a CAS UPDATE
      WHERE status IN ('queued','offered') so exactly one of the two
      polling workers claims the job. The other gets a 204 (no_jobs_available)
      response — no double-claim, no partial commit. This is the atomic-
      fair-claim guarantee: the SQL UPDATE under BEGIN IMMEDIATE is the
      single arbiter.
    - The I001 import-sort error was auto-fixed by ruff; no remaining
      import-sort errors.
